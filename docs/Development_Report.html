01 프로젝트 개요

GrowthNote는 초·중·고 담임교사가 학생별 행동특성 및 종합의견(생활기록부 평어)을 효율적으로 작성할 수 있도록 돕는 AI 기반 웹 애플리케이션이다.

핵심 가치

  • Privacy First: 학생 이름·성별·평어 등 일체의 개인정보가 외부 서버로 전송되지 않고 교사 브라우저의 localStorage에만 저장된다.
  • BYOK (Bring Your Own Key): 교사 개인 Google Gemini API Key를 직접 등록하여 사용하므로 중앙 서버 병목 없이 빠른 응답이 보장된다.
  • 교육부 기재요령 준수: 종결 어미(~함., ~임., ~음., ~됨.), 미래지향적 순화 표현, 비교·서열화 금지 원칙을 AI 프롬프트에 내재화했다.
  • 1·2학기 연속성 관리: 1학기 평어를 AI가 맥락으로 참고하여 2학기 평어 작성 시 중복 서술을 자동 회피한다.

개발 동기

  • Electron 기반 데스크톱 앱으로 먼저 개발 → 교사 간 공유가 어렵고 설치 부담이 큰 문제를 인식
  • Vite + React + TypeScript 웹 버전으로 전면 재구축
  • GitHub Pages 무료 배포를 통해 URL 하나로 모든 기기에서 접속 가능하도록 개선

04 주요 기능 명세

4.1 인증 시스템

관리자 계정 (admin)

  • 하드코딩된 비밀번호 없음. 첫 접속 시 관리자가 직접 비밀번호를 설정하는 온보딩 플로우.
  • 설정된 비밀번호는 SHA-256으로 해시화 후 adminPasswordHash 필드에 저장.
  • 관리자 로그인 후 교사 계정 관리(목록 조회·비밀번호 초기화·계정 삭제) 가능.

교사 계정

  • 회원가입 시 아이디 중복 확인 → SHA-256 해시 저장 → users 맵에 기록.
  • 로그인 성공 시 세션 메모리에 평문 비밀번호 임시 보관 → API Key AES 복호화에 활용.
  • 이전 버전 단일 교사 계정(passwordHash)과의 하위 호환성 유지.

API Key 보관

  • "이 브라우저에 안전하게 저장" 체크 시: AES-GCM 암호화 후 encryptedKey로 저장. 비밀번호 없이는 복호화 불가.
  • 미체크 시: 세션 메모리(React state)에만 임시 보관 → 탭 종료 시 자동 소멸.

05 보안 설계

비밀번호 해시 흐름

[평문 비밀번호]
    │
    ▼ SHA-256 (Web Crypto API crypto.subtle.digest)
[64자리 16진수 해시]
    │
    ▼ localStorage 저장
adminPasswordHash / users[username]

API Key 암호화 흐름

[Gemini API Key 평문]
    │
    ▼ AES-GCM (12-byte 랜덤 IV, 파생키: SHA-256(교사 비밀번호))
[IV:암호문 hex 문자열]
    │
    ▼ localStorage 저장 (encryptedKey)

교사마다 다른 비밀번호로 암호화되므로, 같은 브라우저를 공유해도 타인이 API Key를 복호화하는 것이 불가능하다.

  • 개발용 메모 파일(docs/관리자.txt) 삭제 완료.
  • 과거 문서에 기재된 비밀번호 문자열 전면 소독 처리.

07 서비스 레이어 상세

webStorage.ts

  • saveConfig / loadConfig: AppConfig CRUD
  • saveClassData / loadClassData / deleteClassData: 학생 데이터 CRUD
  • listClasses: 교사별 학급 목록 조회
  • saveClassJson: KST 날짜 기반 JSON 파일 다운로드
  • loadClassJsonFromFile: FileReader 기반 JSON 복원

webCrypto.ts

  • hashPassword(password): crypto.subtle.digest('SHA-256') → hex 문자열
  • encryptKey(text, secret): AES-GCM 암호화 (12-byte 랜덤 IV)
  • decryptKey(encryptedText, secret): AES-GCM 복호화

authService.ts

  • login(): admin 분기 처리 + 구버전 하위 호환 로직
  • register(): 아이디 중복 확인 + 해시 저장
  • resetUserPassword(): 비밀번호 assess1234로 초기화
  • deleteUser(): 계정·학급 데이터 일괄 삭제
  • adminListAllData(): 관리자 대시보드용 전체 데이터 조회

geminiService.ts

  • REST API 직접 호출: POST /v1beta/models/{model}:generateContent
  • systemInstruction 분리 전달 (시스템 프롬프트 + 사용자 프롬프트 이원화)
  • 모델별 generationConfig 분기 처리
  • 한국어 친화 에러 메시지 파싱 (getFriendlyErrorMessage)

excelService.ts

  • parseStudentExcelFile(): ArrayBuffer → xlsx 파싱 → StudentInput[]
  • downloadTemplateExcel(): 빈 양식 xlsx 생성·다운로드
  • exportResultsExcel(): 스타일 적용 결과 xlsx 생성·다운로드

10 한국 표준시(KST) 날짜 처리

⚠️
문제: new Date().toISOString()은 UTC 기준이므로, KST(UTC+9) 자정 이전 시간대(00:00~08:59)에 파일을 저장하면 전날 날짜로 파일명이 생성된다.
✅
해결: Asia/Seoul 타임존을 명시적으로 지정하여 로컬 날짜 컴포넌트를 추출한다.
// ❌ 잘못된 방법
const date = new Date();
const yyyy = date.getFullYear(); // UTC 기준

// ✅ 올바른 방법 (webStorage.ts, excelService.ts)
const koreaDate = new Date(
  new Date().toLocaleString('en-US', { timeZone: 'Asia/Seoul' })
);
const yyyy = koreaDate.getFullYear();

11 GitHub Actions 배포 파이프라인

⚠️
주의: GitHub이 자동 생성하는 static.yml은 빌드 없이 소스코드 원본을 배포하므로 React 앱에서 빈 화면 문제 발생. 반드시 삭제하고 deploy.yml 단독 사용.

워크플로우 흐름 (.github/workflows/deploy.yml)

push to main
    │
    ▼ [build job]
  1. actions/checkout@v4        ← 소스코드 체크아웃
  2. actions/setup-node@v4      ← Node.js 20 + npm 캐시
  3. npm ci                     ← 의존성 정확 설치
  4. npm run build              ← tsc + vite build → ./dist
  5. actions/configure-pages@v5
  6. upload-pages-artifact@v3   ← ./dist 업로드
    │
    ▼ [deploy job]
  7. actions/deploy-pages@v4    ← GitHub Pages 배포

핵심 설정 (vite.config.ts)

export default defineConfig({
  plugins: [react()],
  base: '/growth-note/', // 저장소 이름과 반드시 일치해야 함
})
